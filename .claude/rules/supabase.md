# Supabase 연동 규칙 (데이터 계층)

- **학원 격리는 클라이언트가 아니라 RLS로 강제한다.** 모든 테이블(teacher·student·schedule·
  evaluation)에 "요청자의 academy_id와 일치하는 행만" 정책을 건다. 클라이언트의
  `.eq('academy_id', ...)` 필터는 UX용일 뿐 인가가 아니다 — 필터를 빼도 타 학원 데이터가 새지 않아야 한다.
- **여러 행을 원자적으로 묶어야 하는 연산은 서버 RPC로.** 예: 회원가입 시 학원 생성+소속 연결,
  초대 코드 검증+참여. 클라이언트에서 다단계 write로 흉내내지 않는다.
- **service_role 키는 클라이언트에 절대 노출 금지.** 브라우저 번들에는 anon 키만. 서버 전용
  키가 필요한 연산은 RPC/서버 측에 둔다. (게이트 NO_HARDCODED_SECRET가 1차로 잡지만 배치도 규칙)
- **쿼리·RPC 응답은 신뢰 경계 밖.** shared/api는 반환값을 그대로 도메인에 넘기지 말고 경계에서
  파싱·검증한다 (스마트 컨스트럭터로 도메인 값 객체 생성).
- 이 파일은 범용 연결/호출 어댑터만 — 도메인 개념(평가 규칙, 시간표 로직)은 여기 두지 않는다
  (그건 entities/features). shared 규칙과 동일: 도메인 지식 유입 금지.
