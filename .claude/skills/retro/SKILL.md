# 회고 — "뭐가 틀렸나"가 아니라 "무엇이 바뀌어야 같은 실수가 안 나나"
## 절차
1. 게이트 실패, 리뷰 지적, 사용자 피드백에서 반복 패턴만 추린다 (1회성은 교훈 아님)
2. 교훈마다: 패턴 / 근거(어디서 몇 번) / 제안(반영 위치)
3. 반영 위치 우선순위 (싼 층으로 내려보내는 압력):
   ① permissions.deny — 선언으로 되면 최선 (0코드)
   ② 게이트 — 정적 검사 가능하면 (0토큰, 100% 강제. gates/는 보호 파일 — 제안만)
   ③ rules/조건부 문서 — 특정 경로·상황에만 필요한 규칙
   ④ CLAUDE.md — "어기면 협업이 깨지는" 수준일 때만 (상시 고정비)
4. 사용자 승인 후에만 반영. docs/LESSONS.md 기록은 승인 후 사용자 확인 하에
5. CLAUDE.md가 40줄을 넘보면 기존 규칙의 강등(③으로 이동)을 함께 제안
