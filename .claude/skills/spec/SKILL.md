# 스펙 — 살아있는 설명서 🔓 + 잠긴 계약 🔒

docs/references/templates/spec.md 형식으로 활성 프로젝트(루트 ACTIVE)의 projects/<이름>/docs/specs/$ARGUMENTS.md 를 작성한다.

## 절차

1. **사용자 이야기 인터뷰** — 행위자를 나열하면 질문이 나온다("강사도 이 기능을 쓰나?" 류).
   선택지 제시 방식 권장. <누가>로서 <뭘> 원하는지·왜인지를 행위자별로(실제로 다른 것만).
2. **동작·화면 인터뷰** — 흐름 → 입력·검증 → 성공/실패 → 규칙, 그리고 쓰는 페이지를 정한다.
   이때 docs/references/modeling-checklist.md 를 **깊게 훑어** 이 기능에 걸리는 항목을 질문으로 전환한다
   (선택지·트레이드오프를 함께 제시하는 방식).
3. **동작 중 "어기면 사고"를 불변식으로 승격** — ID 부여, 강제 위치(서버/RLS/게이트)·위반 시 결과 명시.
4. **시나리오**(불변식마다 실패 경로 1개 이상)·**신뢰 경계**(믿는 값·안 믿는 값)·**비범위**.
5. 사용자 **승인** 요청 → 승인 시: status를 approved로 바꾸고
   `node scripts/seal-spec.mjs <스펙경로>` 실행 (inv_hash 기록 — 불변식 봉인).

## 재승인 (불변식 변경 시)

- 불변식(🔒)을 바꿔야 하면 status를 draft로 되돌리고, 변경 후 재승인·재봉인(seal-spec 재실행)한다.
  🔓 구역(사용자 이야기·동작·화면)은 승인 후에도 코드보다 먼저 자유롭게 갱신한다.

## 금지

- 산문은 🔓 구역에. 불변식 섹션은 ID+판정 가능 문장만.
- 사용자 승인 없이 status: approved 변경 금지
