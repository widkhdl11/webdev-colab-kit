## 한 줄 요약

학원 선생님들이 학원 단위로 학생의 시간표·월간 평가·시험 성적을 공유·관리하고,
월간 평가표를 이미지/PDF로 내보내며, 과목별·시험별 성적 통계를 보는 학생 관리 사이트.

## 목적과 대상

- 목적: 학원 학생의 등록·시간표·월간 평가·시험 성적 관리 (학원 단위 공유)
- 대상: 한 학원에 소속된 선생님들 (로그인 사용자). 여러 과목 선생님이 같은 학생을 담당·평가

## 모델링 플래그 (설계 단계 — modeling-checklist 훑기 2026-07-23)

필드 단위 훑기에서 나온 함정. `/spec`으로 INV 확정할 것과 결정만 필요한 것을 구분한다.
근거·선택지: docs/references/modeling-checklist.md

- 🔴 **평가완료 상태·최근평가월 = 시변/파생** (학년과 동일 계열, **이미 목록 화면에 저장필드로 나감**).
  evalStatus·lastEvalMonth는 (현재월, 이달 평가 존재)에서 파생해야 함 — 저장 금지. "완료" 정의(전 과목/일부) 확정.
  → **스펙 필요: 평가완료-시변** · 출고된 인스턴스는 파생으로 교정 대상.
- 🔴 **학생 재원 상태 전이** (재원→휴원→퇴원→복원?). 미모델링. 휴원생의 통계·목록·정원 포함 여부.
  → **스펙 필요: 재원상태-전이**
- 🔴 **삭제 시 기록 보존**. 퇴원생 성적·평가, 퇴사 교사의 작성자 참조. 하드삭제 금지·소프트삭제 원칙.
  → **스펙 필요: 삭제-보존** (auth-isolation 스펙에 얹기 가능)
- 🔴 **학생↔과목 카디널리티 1:N**. 한 학생이 여러 과목 수강(과목마다 요일·시간 상이) → 과목은
  학생 단일 필드가 아니라 시간표(수강)에서 파생. 학생 등록 폼에서 과목 제거함(→시간표에서 관리).
  → **스펙 필요: 학생-과목 1:N — 시간표 파생** (읽기모델 subjects는 현재 목업 denormalize)
- 🔴 **통계 시간축·비교** (통계 화면 요구에서 확정). 시간 단위 = **학기(1·2학기)+연도**, 기본 1년,
  **작년 동일 시험 비교** → exam_score에 학기·연도 식별 필요(date 파생 or 필드), 그리고 **연도 간 "동일 시험"
  식별자**(시험종류+학기+과목이 comparable해야 작년과 매칭). 또 **학년별 통계는 시점 학년 문제**(학년은
  파생·시변 — "작년 중3" vs "올해 중3"은 다른 학생) → 집계 기준 시점 확정.
  **평균 정의 = 학생별 평균을 먼저 내고 그 평균들의 평균(학생 동등 가중)** — 과목 점수를 전부 더해
  개수로 나누면 다과목 학생이 과대 반영됨(금지). 미실시 시험은 집계 제외. → **스펙 필요: 통계 집계 축·평균 정의**
- 🔴 **시험 = 정기(중간·기말) vs 비정기(학원·모의) 구분**. 정기=연도+학기+종류로 자동 식별(시험명 불필요),
  비정기=이름+시기 입력(인스턴스 구별). **점수 입력 폼: 시험명은 비정기일 때만** 노출(구현 반영). **통계 추이는
  정기고사만**(고정 4시점). **학원/모의 통계는 나중에 추가**(별도 시간축 — 부정기라 4칸 격자에 안 맞음). →
  **스펙 필요: 시험 종류 구분·시험명 조건부·정기시험 식별자**
- 🟡 **학원(academy) 필드 = 학원명·지점명·전화번호** (인증 시안에서 확정). 지점명 도입 →
  **학원↔지점 카디널리티 미정**: 한 학원에 여러 지점이면 지점이 별도 엔티티(1:N)이고 격리 단위가
  학원인지 지점인지 auth-isolation 스펙에 영향. → **결정 필요 + auth-isolation 스펙에서 확정**
- 🟡 **과목(subject) 자유문자열 → 엔티티/코드화 검토**. rename 소급 안 됨·통계 분열 위험. → **결정 필요(DECISIONS)**
- 🟡 **유일성·중복**: 동명이인 구별 수단 / 시간표 시간 겹침 / 시험 중복 입력. → **스펙(중복 방지) + UI(동명이인 구별)**
- 🟡 **기준 시점·단위**: 진급 기준일 3/1(Asia/Seoul) · "이번 달" 시간대 · 점수 단위/만점 가변. → **스펙에 포함**
- 🟡 **시간표 슬롯 요일 다중**: 한 수업이 여러 요일(월·수 등)에 열림 → `ScheduleSlot.weekday`를
  배열로(또는 요일당 슬롯). 시간표 관리 UI는 다중 선택 반영함(fixture). → 데이터 계층
- 🟡 **교차 테이블 학원 무결성** (security-reviewer 2026-07-24, LOW-MEDIUM, 이월). evaluation/schedule의
  student_id가 타 학원 학생을 가리켜도 RLS는 academy_id만 보므로 통과 → 내 학원 밑에 타 학원 학생 참조 행 생성
  가능(직접 유출 아님, 무결성 오염). 지금은 student/schedule/evaluation이 목업 repo라 미도달. → **student·시간표·
  평가 데이터 계층 배선 시** guard/정책에 "참조 student의 academy = current_academy_id()" 검증 추가.
- 🟢 **전학 시 과거 학교 이력**: 과거 평가표에 그때 학교로? (낮음 — 추후)

## 참고사항

- 평가는 두 종류: **월간 서술 평가**(학부모용, 이미지/PDF) + **시험별 점수 이력**(통계용). 둘 다 유지.
- 학생 개인정보(미성년자) 취급 → 학원 단위 접근 제어가 핵심 불변식.
- 데이터 모델 (스키마에서 확정): academy · teacher · student(이름·**birth_date**·학년·학교·담당과목) · schedule ·
  evaluation(서술·월) · **exam_score(student, 과목, 시험종류, 시기, 점수) — 신규, academy_id RLS 동일 적용**.
  → **DB 파킹 중**: `projects/wama/supabase/migrations/0001_init.sql`에 exam_score 테이블 추가 필요(데이터 계층 재개 시).
