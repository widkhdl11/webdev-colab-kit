# PRODUCT.md — 만들 제품 (정의 + 스코프)

> 제품 정의+스코프 문서(프로젝트당 1개). 스코프가 바뀔 때만, 사용자 동의로 갱신한다.
> 필수 기능은 체크박스로 관리 — 브리핑이 진행률로 집계. 각 기능의 동작·불변식은 docs/specs/ 스펙에 산다.

## 한 줄 요약

학원 선생님들이 학원 단위로 학생의 시간표·월간 평가·시험 성적을 공유·관리하고,
학부모에게 보낼 시간표·결제 안내 이미지를 내보내며, 과목별·시험별 성적 통계를 보는 학생 관리 사이트.

## 목적과 대상

- 목적: 학원 학생의 등록·시간표·월간 평가·시험 성적 관리 (학원 단위 공유)
- 대상: 한 학원에 소속된 선생님들 (로그인 사용자). 여러 과목 선생님이 같은 학생을 담당·평가

## 선택 기능

- (미정) — 후보: 학원 구성원 관리, 다크 테마
- 결제 안내 이미지 **여러 학생 일괄 내보내기** — 1명 단위를 먼저 만들되, 데이터 모델은 일괄이
  가능하도록 설계한다(수강료를 학생에 저장). 확장은 반복문 수준 (결정 2026-08-03)

## 비범위 (만들지 않는 것)

- 학생/학부모 로그인, 알림/문자 자동 발송 — 로그인 없이 미성년자 정보에 닿는 경로를 열지 않는다
- **PG(결제대행) 연동·온라인 수납** — 지금은 "계좌로 입금해달라는 안내 이미지"까지. 결제 요청
  서비스는 별도 스펙으로 다시 판단 (결정 2026-08-03)
- **수납 관리**(납부 여부·미납 추적·입금 대사) — 청구 이력 엔티티가 필요해지는 별개 기능
- **월간 평가표를 학부모에게 내보내기** — 서술 평가는 앱 안에서 선생님끼리 공유하는 용도.
  내보낼 계획 없음 (결정 2026-08-03, 구 필수 기능에서 교체)

## 페이지 구성

- 회원가입 / 로그인 (+ 학원 생성 / 참여)
- 학원생 목록
- 학생 상세 (시간표 + 월간 평가 이력 + 시험 성적 + 결제 안내 이미지 내보내기)
- 학생 평가 입력 (월간 서술) / 시험 점수 입력
- 학생 등록 / 수정
- 성적 통계 (과목별·시험별 그래프/목록)
- 학원 설정 (입금 계좌 · 결제 안내 기본 문구) — 결제 안내 이미지가 참조

## 기술 결정 (프리셋: TypeScript + FSD — 하네스 전제)

- UI 프레임워크: **React 19** — 확정 (2026-08-05)
- 빌드/렌더링: **Vite + SPA(CSR) + FSD** — 확정. SSR 없음
- 라우팅: **react-router-dom (HashRouter)** — `#/students/:id` 형태 유지, 정적 호스팅 친화

- 데이터 계층: **Supabase** — 학원 격리는 서버(RLS)가 강제
- 인증: Supabase Auth (이메일/비밀번호) _(가정)_
- 배포: 정적 호스팅 _(가정 — 미확정)_

## 참고

- 평가는 두 종류: **월간 서술 평가**(선생님 간 공유·앱 내부용) + **시험별 점수 이력**(통계용). 둘 다 유지.
  ~~학부모용 이미지/PDF~~ → 학부모에게 나가는 건 평가가 아니라 **시간표·결제 안내**다 (2026-08-03 교체).
- 학생 개인정보(미성년자) 취급 → 학원 단위 접근 제어가 핵심 불변식.
- 내보낸 이미지에는 **계좌번호와 청구 금액**이 박힌다 → 잘못된 학부모에게 전송되는 것 자체가 사고.
  누구 것인지 즉시 보이게(이름 강조) + 파일명에 학생명·월 반영.
