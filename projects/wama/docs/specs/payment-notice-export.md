## 사용자 이야기 🔓
- 학원 선생님으로서, 한 학생의 **수업 시간표와 이번 달 수강료를 한 장의 이미지**로 만들어
  학부모에게 카톡/문자로 보내고 싶다. 왜냐면 매달 학생마다 시간표와 금액을 따로 적어 보내는 일이
  번거롭고, 손으로 옮기다 **금액이나 계좌를 틀리면 돈 사고**가 되기 때문이다.
  <!-- 행위자 1종: 학원 구성원 누구나(원장/과목교사 구분 없음 — 현행 권한 모델 유지). 학부모는 이 앱의 사용자가 아니다. -->

## 동작 🔓

### 금액이 정해지는 방식 (이 기능의 심장)
청구액은 **저장된 가격표에서 자동으로 계산**한다. 손으로 총액을 적어두지 않는다.

- **과목 가격표**(학원 단위): `(과목, 주 횟수) → 월정액`. 예) 수학 주3회 = 250,000원 / 수학 주2회 = 180,000원 / 논술 주1회 = 120,000원.
- **주 횟수는 시간표에서 파생**한다. 그 학생의 해당 과목 주간 슬롯 개수(`수학 = 월·수·금` → 주3회). 저장하지 않는다. → INV-PN7
- **학생별 과목 예외**: `(학생, 과목) → 월정액` 덮어쓰기. 형제 감면·개별 할인은 여기로 표현한다.
- **한 과목의 금액** = 학생별 예외가 있으면 그것, 없으면 가격표 값.
- **청구액** = 그 학생이 듣는 과목들의 금액 **합**.
- **한 달은 주 수와 무관하다.** 4주인 달과 5주인 달의 금액이 같다(월정액). 달력으로 회차를 세지 않는다.
- **공휴일·휴원 자동 차감 없음.** 조정이 필요하면 내보내기 화면에서 이번 건만 금액을 고친다.

가격표에 **없는 조합**(예: 수학 주4회가 미등록)이면 그 과목 금액을 **빈칸**으로 두고 내보내기 화면에서 직접 입력받는다.
자동으로 0원 처리하거나 가까운 횟수로 대체하지 않는다. → INV-PN6

```
수학 주3회   250,000 → 220,000   (김서연 예외)
논술 주1회   120,000
사회 주4회   [ 직접 입력 ]        (가격표에 없는 조합)
──────────────────────────
합계         입력 후 확정
```

### 흐름
1. 학생 상세 페이지 → **"수강료 안내 이미지"** 버튼.
2. 내보내기 화면이 열린다. 대상 월(기본=이번 달, Asia/Seoul 기준)·과목별 금액·합계·안내 문구가 이미 채워져 있다.
3. 필요하면 이 자리에서 **대상 월 · 금액 · 안내 문구 · 추가 문구**를 고친다. **여기서 고친 값은 이번 이미지에만 적용되고 저장되지 않는다.** → INV-PN5
4. 미리보기를 확인하고 **PNG로 저장**한다. 파일명: `<학생명>_<YYYY-MM>_수강료안내.png`.
5. 선생님이 그 파일을 카톡·문자로 직접 보낸다. 앱은 전송에 관여하지 않는다.

### 이미지에 담기는 것
학원 브랜드 마크 · **대상 월** · 학생(이름·학년·학교·생년) · 시간표(과목=행, 요일 나열 — **시간은 싣지 않는다**) ·
청구 금액 · 입금 안내(기본 문구 + 은행·계좌번호·예금주) · 추가 문구 · 꼬리(학원명·지점·전화).
<!-- 2026-08-04 시안 개정으로 시간 열 제거(🔓 갱신 — 불변식 무관, 재봉인 불필요).
     카드 규격도 "1080×1350 고정"에서 "폭 1080 고정·높이 가변(최소 1350)"으로 바뀌었다. -->
과목이 많을수록 카드가 길어진다(과목 1행 = 68px). **과목 수 상한을 둘지는 미결** — 6과목이면 1080×1566 이다.
**서술 평가 내용·생년월일 전체·연락처·주소는 담지 않는다.** → INV-PN3
시각 규격은 design-rules.md "학부모 전달용 출력물" 블록이 단일 진실이다.

### 안내 문구
- 학원 설정에 **기본 문구**를 저장하고 편집할 수 있다. 매달 재사용한다.
- 문구 안의 `{학생명}` `{월}` `{금액}` 은 이미지 생성 시 치환된다. 알 수 없는 자리표시자는 **치환하지 않고 그대로 둔다**(조용히 지우면 문장이 깨진 채 나간다).
- 내보내기 화면에서 문구를 고쳐도 학원 기본 문구는 바뀌지 않는다(이번 건만).

### 입력과 검증

| 칸 | 필수 | 규칙 | 어기면 뜨는 말 |
|---|---|---|---|
| 대상 월 | Y | YYYY.MM. 기본값=이번 달(Asia/Seoul). 과거·미래 선택 가능 | "대상 월을 선택해주세요" |
| 과목별 금액 | Y | 0 이상 정수(원), 소수·음수 금지, 상한 10,000,000 | "금액은 0 이상 정수로 입력해주세요" |
| 합계 | — | 과목 금액의 합(읽기 전용). 빈 과목이 있으면 합계 미확정 | "금액이 비어 있는 과목이 있습니다" |
| 안내 문구 | Y | 1~500자 | "안내 문구를 입력해주세요" |
| 추가 문구 | N | 200자 이내 | "추가 문구는 200자까지 입력할 수 있습니다" |
| 은행 | Y(학원 설정) | 자유 입력 1~20자 | "은행명을 입력해주세요" |
| 계좌번호 | Y(학원 설정) | 숫자·하이픈만, 8~20자 | "계좌번호는 숫자와 하이픈만 입력할 수 있습니다" |
| 예금주 | Y(학원 설정) | 1~20자 | "예금주를 입력해주세요" |
| 과목 가격표 금액 | Y(과목 관리) | 0 이상 정수(원), 상한 10,000,000 | "금액은 0 이상 정수로 입력해주세요" |

금액은 **원(KRW) 고정**이다. 다른 통화는 없다. 표시는 `450,000원`(콤마 + '원', 한글 병기 없음).

### 성공 / 실패
- **성공**: PNG 파일이 브라우저에 다운로드된다. 화면은 그대로 남아 다시 뽑을 수 있다.
- **금액 미확정**: 빈 과목이 하나라도 있으면 저장 버튼이 비활성. 어느 과목이 비었는지 표시한다.
- **입금 계좌 미설정**: 학원 설정에 은행·계좌번호·예금주가 없으면 생성을 막고 학원 설정으로 안내한다.
  (계좌 없는 입금 안내는 무의미하고, 빈칸이 박힌 이미지가 학부모에게 가면 사고다.)
- **시간표 없음**: 경고 후 허용한다. 시간표 없이 수강료만 안내하는 경우가 있다.
- **이미지 생성 실패**: 오류 메시지 + 재시도. **일부만 그려진 이미지를 내려주지 않는다**(빈손이 틀린 청구서보다 낫다).

### 규칙
- 내보내기 화면의 수정은 전부 **이번 건 한정**이다. 저장값을 바꾸려면 각자의 자리(학생 수정 / 과목 관리 / 학원 설정)에서 고친다.
- 발송 이력을 남기지 않는다. "보냄/안 보냄" 상태는 없다.
- 과거 달을 뽑아도 **지금 정보**로 만든다(그때의 학교·학년·금액으로 재현하지 않는다).
  <!-- 횡단 결정 2026-08-03: _cross-cutting "전학 시 과거 학교 이력" 소진. 재현하려면 발행 스냅샷 저장이 필요하고 그건 수납 관리(비범위). -->
- 동명이인이 있으면 파일명이 겹친다. 브라우저 기본 동작(`(1)` 접미)에 맡기고 여기서 발명하지 않는다.
  <!-- 동명이인 구별은 앱 전체 미결(_cross-cutting) — student-registration 몫. -->

## 화면 🔓
- **학생 상세** — "수강료 안내 이미지" 버튼 (진입점).
- **수강료 안내 내보내기** — 대상 월·과목별 금액·합계·문구 편집 + 미리보기 + 저장. 기존 폼 언어의 반복(빠른 경로).
- **과목 관리** — 과목마다 `(주 횟수, 월정액)` 가격표 편집. **신규 확장**.
- **학생 등록/수정** — 과목별 금액 예외 입력. **신규 확장**.
- **학원 설정** — 은행·계좌번호·예금주·기본 안내 문구. **신규 화면**.

## 불변식 🔒 (계약 — 승인 후 변경은 재승인 필요)
- INV-PN1: 이미지에 실리는 학생·시간표·과목 가격·학생별 예외·계좌 정보는 모두 요청자 학원(current_academy_id())으로 스코프된 데이터여야 한다. 타 학원 데이터는 어떤 이미지에도 들어갈 수 없다. (강제: 서버 RLS — auth-isolation 정책) — 위반 시: 타 학원 미성년자 정보·계좌가 이미지로 유출.
- INV-PN2: 금액은 원 단위 **정수**로만 저장·계산·표시한다. 소수·음수를 허용하지 않는다. (강제: 입력 검증 + DB 제약 + 테스트) — 위반 시: 부동소수 오차가 섞인 청구액이 학부모에게 나간다.
- INV-PN3: 이미지에 서술 평가 내용·생년월일 전체·연락처·주소를 포함하지 않는다. (강제: 렌더 입력 모델이 해당 필드를 갖지 않음 + 테스트) — 위반 시: 미성년자 개인정보가 카톡으로 유출되고 회수 불가.
- INV-PN4: 이미지에는 학생 이름과 대상 월이 반드시 보인다. 둘 중 하나라도 비면 이미지를 생성하지 않는다. (강제: 생성 전 검증 + 테스트) — 위반 시: 누구 것인지 모르는 청구서가 나가고 오발송을 알아챌 수단이 사라진다.
- INV-PN5: 내보내기 화면에서 고친 금액·문구는 저장된 값(학생별 예외·과목 가격표·학원 기본 문구)을 변경하지 않는다. (강제: 내보내기 경로에 쓰기 없음 + 테스트) — 위반 시: 이번 달만 조정한 금액이 영구 반영돼 다음 달부터 틀린 청구서가 나간다.
- INV-PN6: 가격표에 없는 (과목, 주 횟수) 조합을 0원이나 다른 횟수의 금액으로 대체하지 않는다. 금액 미확정 상태로 두고 이미지 생성을 막는다. (강제: 계산 로직 + 생성 전 검증 + 테스트) — 위반 시: 청구액이 조용히 적게(또는 많게) 나가고 아무도 알아채지 못한다.
- INV-PN7: 과목의 주 횟수는 시간표에서 조회 시점에 계산한다. 학생·과목에 저장하지 않는다. (강제: 도메인 계산 함수 + 테스트) — 위반 시: 시간표를 고쳐도 금액이 따라가지 않아 낡은 청구액이 나간다.

## 시나리오 (각각 어느 불변식 검증인지 ID 참조 — 실패 경로 필수)
- S1 (INV-PN1): Given 학원 A·B에 각각 학생과 과목 가격표가 있다 / When A 소속 선생님이 학생 이미지를 만든다 / Then 금액·시간표·계좌 어디에도 B의 데이터가 들어가지 않는다. B의 학생 id를 직접 지정해도 조회가 빈손이다.
- S2 (INV-PN2): Given 금액 칸에 `180000.5` 또는 `-10000` 을 입력한다 / When 저장·생성을 시도한다 / Then 검증에서 막히고 이미지가 만들어지지 않는다.
- S3 (INV-PN3): Given 그 학생에게 이번 달 서술 평가와 생년월일이 저장돼 있다 / When 이미지를 생성한다 / Then 이미지에는 평가 본문도 생년월일도 나타나지 않는다(생년은 연도만).
- S4 (INV-PN4): Given 대상 월을 비운다 / When 저장을 누른다 / Then 이미지가 생성되지 않고 대상 월을 요구한다.
- S5 (INV-PN5): Given 김서연의 저장된 수학 금액이 220,000원이다 / When 내보내기 화면에서 300,000원으로 고쳐 이미지를 만든다 / Then 이미지에는 300,000원이 찍히고, 다시 열었을 때 값은 여전히 220,000원이다.
- S6 (INV-PN6): Given 수학 주4회 가격이 가격표에 없다 / When 수학을 주4회 듣는 학생의 이미지를 만들려 한다 / Then 그 과목이 빈칸으로 표시되고 저장 버튼이 비활성이며, 0원으로 합산되지 않는다.
- S7 (INV-PN7): Given 수학 주3회(250,000원)인 학생의 시간표에서 금요일 슬롯을 지운다 / When 내보내기 화면을 연다 / Then 수학이 주2회로 계산돼 180,000원이 자동 반영된다.

## 신뢰 경계
- **믿는 값**: 서버 RLS가 학원으로 스코프해 돌려준 행(학생·시간표·과목 가격표·학생별 예외·학원 계좌 정보). 격리는 서버가 강제한다.
- **안 믿는 값**: 클라이언트가 보낸 학생 식별자·학원 식별자(최종 격리는 RLS가 재확인), 내보내기 화면에서 사람이 타이핑한 금액·문구(범위·형식·길이를 재검증), 클라이언트가 계산한 합계(생성 직전 재계산해 대조).
- 이미지 생성은 클라이언트에서 일어난다. **서버에 이미지를 보관하지 않는다** — 보관하면 그 자체가 새로운 유출 표면이 된다.

## 비범위
- PG(결제대행) 연동·온라인 수납·자동 청구.
- 납부 여부 추적·미납 관리·입금 대사.
- 공유 링크·이메일/문자 자동 발송 (로그인 없는 접근 경로를 열지 않는다).
- **여러 학생 일괄 내보내기** — 선택 기능으로 미룸(PRODUCT). 데이터 모델은 일괄이 가능하도록 설계하되 화면은 만들지 않는다.
- 발송 이력 보관, 과거 시점 재현(발행 스냅샷).
- 공휴일·휴원 캘린더와 자동 차감.
- 회당 단가 × 실제 달력 회차 계산 (월정액으로 확정).
- PDF·A4 출력 (PNG 카드 단일).
- 퇴원 학생 처리 — 퇴원 개념 자체가 아직 없다(student-registration 몫).
- 동명이인 파일명 충돌 해소.

## 이 스펙이 데려오는 딸림 변경 (구현 시 함께)
- **과목**: `(주 횟수 → 월정액)` 가격표 추가. 과목 관리 화면 확장 + 마이그레이션.
- **학생**: `(과목 → 월정액)` 예외 추가. 학생 등록/수정 화면 확장 + 마이그레이션.
- **학원**: 은행·계좌번호·예금주·기본 안내 문구 추가. 학원 설정 화면 신규 + 마이그레이션.
- **기존 카피 정정**: 학생 상세의 "평가표 내보내기" 버튼, 평가 입력 화면의 "학부모 전달용 평가표에 들어갈 서술 평가입니다" 문구는 사실과 달라졌다(평가는 내보내지 않는다).
- 셋 다 학원 격리(academy_id 기본값 + RLS)를 0001 패턴 그대로 적용한다. 교차 참조는 `_cross-cutting` 의 "교차 테이블 학원 무결성" 항목을 따른다.
